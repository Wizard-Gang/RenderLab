# Security policy

Report a vulnerability privately using GitHub's **Report a vulnerability** entry in the repository Security tab, when enabled. If that feature is unavailable, contact the repository owner through a private channel. Do not put exploit details or credentials in a public issue or pull request.

RenderLab is a browser rendering platform and a local reference application. It runs no service, holds no account or secret, and needs no game server; local development needs no credential. Its security surface is the content it loads, the dependency graph, GitHub Actions, repository permissions, merge controls and published artifacts.

Every MapLab export, RigLab export, artwork file and compiled resource is untrusted data. The readers that arrive from RLDR-006 onward must bound sizes and counts, reject unsafe or duplicate paths, verify listed sizes and SHA-256 digests, reject unsupported versions and unknown required features, and never evaluate content or inject it as markup. A correct digest proves consistency with a manifest, not the identity or trustworthiness of its publisher. SVG artwork is rasterized as an image, never inserted into the page as live markup.

CI uses read-only permissions. Actions are GitHub-owned and pinned to full commit SHAs. `npm audit --audit-level=high` is a network-backed required check; a vulnerable dependency is updated or removed in a controlled change, never bypassed with an ignore rule. Install scripts are refused unless `package.json` `allowScripts` names them (`strict-allow-scripts`), and Playwright browsers are installed by an explicit command, never by an npm lifecycle script. Dependency and workflow update suggestions are inputs to a controlled `SEC` or `BUILD` change; they do not bypass IDs, review, or exact-head CI. Settings commands read a runtime `GH_ADMIN_TOKEN` or `GH_TOKEN`; keep tokens in process or provider secret state, never in source, PR text, test fixtures, or logs. The repository contract fails any tracked credential-bearing file.
